<InShort>

- We record every significant architecture decision as a short Architecture Decision Record (ADR).
- Each ADR states the context, the decision, the alternatives and the consequences.
- ADRs are never deleted. A new ADR replaces an old one and says so.

## Context

Many organisations and countries build the Genome EDIC system over several years. People need to know why the system looks the way it does, including decisions taken before they joined.

## Decision

We record each significant architecture decision as an ADR in this chapter, using the [ADR template](/decisions/template). An ADR is "significant" when it affects more than one scope, changes an interface, or implements a governance choice.

## Consequences

- Decisions and their reasons stay available to new taskforce members, auditors and Member Countries.
- Writing an ADR takes time; the template is kept short to limit the effort.
